# Kubernetes 本地卷调度演练（Flask + SQLite）

一个单页 Web 演练台：录入**带节点的本地 PV**（含容量）和**待用 PVC**（含申请容量），
为 Pod 选择候选节点与所需 PVC 后提交调度，页面展示选定节点与 PV-PVC 绑定关系。
检修节点前，值班员还可在「节点空闲卷盘点」页按卷名分页逐卷核对空闲卷（每页最多 50 条）。

## 一、调度规则（与 Kubernetes 本地卷语义对齐）

1. **PV 带节点亲和**：每个本地 PV 固定属于一个节点，只能被该节点上的 Pod 使用。
2. **容量匹配**：PV 容量 ≥ PVC 申请量才可绑定（单位 GiB，正整数）。
3. **候选节点按序尝试**：对每个候选节点判断能否满足本次**全部** PVC，
   第一个可行的节点即被选定，并在同一事务内落库本次新绑定。
4. **已绑定 PVC 沿用原卷（节点粘性）**：已绑定的 PVC 不再参与选卷，使用它的 Pod
   只能被调度到该卷所在节点；若候选节点与之无交集，直接判定失败并说明原因。
5. **选卷策略**：未绑定 PVC 按申请量降序处理，每个 PVC 在目标节点的空闲卷中选
   **容量最小且够用**的一卷（最小适配，给大 PVC 留大卷）。
6. **凑不齐即失败**：所有候选节点都无法满足时，给出每个节点的具体卡点（无空闲卷 /
   容量不足 / 节点粘性冲突），**保留原有绑定，本次不新增任何绑定**，仅写一条失败审计记录。

## 二、并发安全（同一 PVC 只绑一次、同一 PV 只分给一个 PVC）

两层保障：

| 层级 | 手段 | 作用 |
| --- | --- | --- |
| 事务 | 每次调度以 `BEGIN IMMEDIATE` 开启 | 立即获取写锁，并发提交在数据库层串行化，避免死锁与读后写竞争 |
| 约束 | `binding.pv_id UNIQUE`、`binding.pvc_id UNIQUE` | 数据库硬兜底：并发撞车时 `IntegrityError` → 整笔回滚，原有绑定不受影响 |

- 多 PVC Pod 的多笔新绑定在**同一事务**内提交，要么全部成功，要么全部回滚，不会出现半套绑定。
- SQLite 开启 WAL 模式与 `busy_timeout=30s`，锁等待期间请求排队而不是立即报错。
- Flask 以 `threaded=True` 启动，可真实并发处理 HTTP 请求。

## 三、节点空闲卷盘点（按卷名分页，每页最多 50 条）

值班员检修节点前要逐个核对空闲的本地卷。首页「⑤ 节点空闲卷盘点」选择节点后进入
`/inventory`，按卷名升序翻页，每页最多 50 条卷明细。

**盘点语义**

- **范围**：以打开第一页时该节点**已登记且空闲**的卷为准，一轮翻完**不重不漏**。
- **中途新录入的卷留到下一轮**（点「重新开始本轮盘点」即可看到）。
- **原先空闲、中途被占用的卷仍在清单原位置列出**，并显示占用它的 PVC 与绑定时间。
- **同一页的占用状态以一次读取的已提交数据为准**（每页明细由一条 SELECT 完成）。
- 翻页期间**照常录卷和调度**，盘点是只读分页，不阻塞任何写操作。

**实现要点（服务端无状态）**

| 机制 | 做法 |
| --- | --- |
| 圈定范围 | 第一页用**一条 SELECT** 同时读 `pv` 高水位（该节点 `MAX(id)`）与 `binding` 高水位（全局 `MAX(id)`），两个水位来自同一已提交快照 |
| 排除新录入 | `pv.id ≤ pv水位`：id 自增单调，中途新录的卷 id 更大，自然留到下一轮 |
| 排除事先占用 | `NOT EXISTS (binding.pv_id = 卷 AND binding.id ≤ 绑定水位)`：调度以 `BEGIN IMMEDIATE` 串行提交，id 序即提交序，第一页时已占用的卷被精确排除；中途新绑定 id 大于水位，不缩小范围 |
| 稳定翻页 | 卷名 `UNIQUE`，`WHERE name > 游标 ORDER BY name LIMIT 51`（多取 1 条判断是否还有下一页，页面只展示 50 条） |
| 占用状态 | 每页一条 SELECT 内 `LEFT JOIN binding/pvc` 实时读出当前占用 |
| 零服务端状态 | 水位与游标全放在翻页链接参数里，**不复制整份清单、不跨请求保留读事务**，每请求各自一条 SELECT |

`/inventory?node=...&format=json` 提供同一查询逻辑的 JSON 视图（含 `scope` 水位与
`next_params` 翻页参数），供自动化试跑脚本逐页核对。

## 四、目录结构

```
.
├── Dockerfile              # python:3.11-slim，启动时幂等建表再起服务
├── docker-compose.yml      # 一条命令启动；SQLite 数据持久化到命名卷 sched_data
├── requirements.txt        # Flask==3.1.3
├── app/
│   ├── __init__.py
│   ├── app.py              # 路由、调度算法、盘点分页、事务与并发控制
│   ├── schema.sql          # 4 张表 + UNIQUE/CHECK 约束
│   └── templates/
│       ├── index.html      # 单页界面（录入 / 调度 / 盘点入口 / 绑定 / 审计 / 重置）
│       └── inventory.html  # 节点空闲卷盘点页（按卷名分页，每页 ≤50）
└── tests/
    └── e2e_test.py         # 纯标准库端到端脚本（HTTP 并发 + 盘点翻页 + 状态断言）
```

数据表：`pv`（本地卷）、`pvc`（声明）、`binding`（绑定，双向 UNIQUE）、
`pod_run`（每次调度的审计记录，含成功/失败与卡点说明）。

## 五、用 Docker Compose 启动

```bash
docker compose up --build
# 打开 http://localhost:5000
```

- 数据存于命名卷 `sched_data`（容器内 `/app/data/sched.db`），容器重建数据不丢。
- 页面上的「清空重置」可一键删空全部演练数据。

不用 Docker 时的本地启动方式（需要 Python 3.11 与 Flask）：

```bash
pip install -r requirements.txt
python -c "from app.app import app, init_db; init_db(); app.run(host='0.0.0.0', port=5000, threaded=True)"
```

## 六、页面操作

1. 「录入本地 PV」：名称、所在节点、容量（GiB），重名会被拒绝。
2. 「录入待用 PVC」：名称、申请容量（GiB），重名会被拒绝。
3. 「为 Pod 提交调度」：填 Pod 名称、逗号分隔的候选节点，勾选一个或多个 PVC 后提交。
4. 「节点空闲卷盘点」：下拉选择节点（显示各节点空闲/总卷数）→「开始盘点」打开第一页，
   按卷名逐页翻看（每页最多 50 条）；翻页期间可回到首页照常录卷、调度，
   中途被占用的卷会在清单原位置标红并显示占用它的 PVC；「重新开始本轮盘点」开启新一轮。
5. 首页下方展示 PVC 清单、当前绑定关系、最近 20 条调度记录。
6. 顶部 flash 条展示本次结论：成功时列出节点与每条 PVC→PV 绑定；失败时说明卡点并确认零新增。

## 七、自动化试跑

`tests/e2e_test.py` 只依赖 Python 标准库，对运行中的服务发真实 HTTP 请求：

```bash
python tests/e2e_test.py            # 默认 http://127.0.0.1:5000
python tests/e2e_test.py http://host:port
```

覆盖：卷跨节点分散调度、最小适配、容量不足/无空闲卷的失败与零新增、已绑定 PVC
节点粘性、已占用 PV 不重复分配、同 PVC 并发只绑一次、不同 PVC 并发抢卷、
多 PVC Pod 并发无半套绑定、200 请求级压力；以及节点空闲卷盘点——分页不重不漏、
每页 ≤50、中途新录入留到下轮、中途被占用卷原位置显示占用 PVC、翻页期间照常录卷调度、
网页渲染与翻页链接。

## 八、实测结果摘要（交付前在本环境实测）

- 端到端脚本 **67 条断言，连续 3 轮全部通过**（调度规则 + 并发安全 + 盘点分页）。
- 盘点分页实测：inv-a 节点 120 卷 → 3 页（50/50/18）不重不漏、整轮严格按卷名升序；
  翻页期间新录 3 卷（卷名分别落在已翻过/中间/未到区域）均不出现、留到下一轮；
  翻页期间被调度占用的 `inv-a-0070` 仍在第 2 页原位置列出并显示占用它的 PVC；
  重新开始一轮后范围正确更替（+3 新录入、-1 已被占用，共 120 条）。
- 网页自测（纯 HTML 页面流，15 项全部通过）：首页节点下拉显示各节点空闲/总卷数；
  第一页恰 50 行；跟随页面「下一页」链接翻页衔接不重不漏；中途被占用卷标红并显示 PVC。
- 并发压力：200 卷盘点翻页（每页间隔 0.4s）与 20 并发调度 + 30 并发录卷同时进行——
  全部请求无 500，一轮 200 条不重不漏，20 个被并发占用的卷在最后一页区域原位置
  标为已占用并显示 PVC，新一轮范围 210 条（200 - 20 已占用 + 30 新录入）。
- 直接对 SQLite 验证：同 PV 重复分配、同 PVC 重复绑定、容量/申请量 ≤ 0、
  重名 PV/PVC、绑定引用不存在的 PV，共 8 项违规均被约束拒绝。
